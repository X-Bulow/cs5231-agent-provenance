# figures 中的 SVG 怎么读

当前共 12 张图：8 张完整时间线、4 张从受保护测试修改出发的局部图。它们由 provenance/render.py 根据 graphs 中的 JSON 绘制，不是模型自己解释行为的示意图。

## 先读懂共同元素

- 从左到右是模型轮次和工具调用的记录顺序，列宽不表示耗时。同一轮可发出多个并发调用，调用编号不能证明它们彼此的因果先后。T1、T2 表示模型轮次；C1、C2 表示该次运行内的工具调用编号。
- 顶部 user prompt 是用户任务。下方每条横线对应一个文件路径，图将这个路径的多个内容版本合在一行展示；JSON 中仍是独立的版本节点。
- 蓝色是初始安装的技能文件，橙色是工作区原有内容，绿色是模型或工具写出后的内容。合法源码修复也会变绿，因此绿色不等于恶意或已被污染。
- 空心圆表示读取，黑方块表示写入，叉号表示删除；v1、v2 是写入后的版本编号。新文件创建前可能没有横线，删除后横线会中断。同一工具调用内的多次写入／删除可能合并成调用结束版本。
- 竖向实线对应直接记录的文件操作，虚线表示根据 Shell 命令等推断的操作。细折线连接工具返回与下一轮，表示记录中的返回被后续轮次接收，不是另一条文件读取。
- 空白描边工具框表示调用报错；它本身不能说明调用恶意，也不证明所有错误工具都完全没有副作用。粗黑框和圈是绘图时人为标出的调查重点，不是自动评分结果。
- 图可达只说明候选依赖。它不证明某条注入指令造成了后续动作，也不证明绿色文件真的被攻击污染。

## 局部图副标题中的数字

副标题按“祖先节点数／完整图除目标外的节点数”计数，两侧都不含查询目标。计数对象包括轮次、调用、返回、用户任务和文件版本，不是文件数或阅读工作量。

| 局部图 | 查询目标之外的祖先节点数（个） | 完整图除目标外的节点数（个） |
| --- | --- | --- |
| run-006-backward-slice.svg | 41 | 128 |
| run-014-backward-slice.svg | 33 | 110 |
| run-016-backward-slice.svg | 29 | 77 |
| run-018-backward-slice.svg | 27 | 88 |

例如，006 的 41/128 表示 128 个其他节点中有 41 个能沿关系到达目标；不能解释为只看 41 个文件就能确认攻击来源。

不是每份运行都有 SVG。graphs 有 16 份可构图记录，本目录只绘制了选定案例与新批次。011、012 等没有对应 SVG，不代表没有原始记录或图数据。
