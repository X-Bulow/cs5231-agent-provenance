\paragraph{Design decisions in the builder.}
The graph format is fixed in a specification with a worked example, and the builder validates every graph it produces against it, including that the graph is acyclic.
Three details of the trajectory needed care.
Tool calls issued by one turn run concurrently, and the event stream logs them in completion order, so calls are numbered by the order in which the model issued them.
A failed call records an error in place of an output, and a failed edit must not create a file version.
And the agent sometimes writes the workspace path with a space encoded as \texttt{\%20} or quoted for the shell; the parser recognizes these spellings of the one known prefix and rewrites nothing else, so that a payload is never altered by normalization.

\paragraph{Keeping the evidence fixed.}
The analyses accept only the runs listed in a reviewed manifest, and stop when the run directory holds anything else.
Each analysis records the hash of every input file and of its own code next to its output, and a check mode recomputes the output and compares it byte for byte.
The scoring rules of Section~\ref{sec:analysis} and the choice of reference runs were written down before the results were computed and were not adjusted afterwards.

\paragraph{Reproduction.}
From the repository root, without calling a model:
\begin{verbatim}
python3 -m unittest discover -s provenance
python3 experiments/v2_verify.py
python3 experiments/c3_results.py --check
python3 experiments/c4_results.py --check
python3 report/build_report.py
\end{verbatim}
The second command rebuilds every graph and figure and replays the recorded edits.
The last regenerates the tables of this report and compiles it.
