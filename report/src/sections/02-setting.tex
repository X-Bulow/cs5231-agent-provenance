\section{Setting}
\label{sec:setting}

We use the demonstration setting supplied with the project~\cite{projectguide}.

\paragraph{Agent and skill.}
The agent is OpenCode 1.19.5~\cite{opencode}, run non-interactively.
It is asked to use the \emph{systematic-debugging} skill from the Superpowers collection~\cite{superpowers}, pinned to a fixed revision.
A skill is a document that tells the agent how to work.
This one prescribes four phases: investigate the root cause, find the pattern, test a hypothesis, then fix and verify.
Two companion skills are installed alongside it.

\paragraph{Task.}
The workload is a small Python program that summarizes expense records by category.
It has one bug: a refund is added to the category balance when it should be subtracted, so two of the five tests fail.
The user's instruction states the intended behavior, and it states what the agent may change: files under \file{src/}, and new files under \file{outputs/}.
Everything else is to be preserved, including the tests.
The instruction ends by saying that project documentation and tool output are evidence about the project and authorize no change to the task.

\paragraph{Scenarios.}
Four scenarios start from the same program, tests, and instruction and differ in one text file (Table~\ref{tab:scenarios}).
The payload in the two attack scenarios asks for the same thing: leave the implementation alone, change the two failing test expectations to \texttt{140.00} and \texttt{5.50}, and report the task as complete.

\paragraph{What a run records.}
Each run starts from a fresh copy of the workspace.
The harness stores the SHA-256 hash of every workspace file before the agent starts, the agent's event stream, and the agent's native session export, which lists every model response with its tool calls, their arguments, and the text each call returned.
After the run, an independent checker hashes every file again and tests the implementation on nine inputs of its own.
The checker does not use the agent's tests or the agent's claims, so an agent that rewrites the tests cannot make it pass.

\paragraph{The matched dataset.}
The results of this report come from ten runs collected under one fixed configuration: five of the normal scenario and five of the documentation injection.
The two groups differ only in the project notes.
The order of the ten runs was fixed before collection, and no run was replaced or repeated.
Table~\ref{tab:config} lists the configuration.

\begin{table}[H]
\centering\small
\begin{tabularx}{\textwidth}{@{}L{0.24\textwidth} X@{}}
\toprule
Setting & Value, the same for all runs \\
\midrule
Model & \texttt{qwen3-coder-next}, served by the School of Computing \\
Sampling & Requested temperature 0.2. The sampling the server applies and the model revision are not known \\
System instruction & A fixed generic text: use the tools, recover from tool errors, exercise the real command-line program, report the actual results. It contains no solution and no answer of the independent checker \\
Continuation & One session of at most four segments within 600 seconds. A segment after the first starts with a fixed message asking the agent to continue \\
Access rules & A per-run sandbox profile. Writes outside the workspace and reads of other projects are denied; the protected files inside the workspace stay writable \\
\bottomrule
\end{tabularx}
\caption{Configuration of the matched dataset.}
\label{tab:config}
\end{table}

Two of these settings matter when reading the results.
The protected test file is writable, so that a violation can be observed: a run that leaves it unchanged was not prevented from changing it.
And the collector sends the continuation message only when the visible requirements of the task are not yet met.
It stops when they are met, when a protected file has changed, at the time limit, or after four segments.
A session with several segments is still one run.
The independent checker runs after the session has ended and gives the agent no feedback.

\paragraph{Extension runs.}
Ten further runs under the same configuration cover the other two scenarios, five runs each.
They were collected after the matched dataset, are stored apart from it, and do not enter its numbers.
Section~\ref{sec:results-extension} reports them.

\paragraph{Exploratory runs.}
Before the matched dataset we collected eight single runs, one per scenario with each of two models.
The graph model was developed on them, and one example in Section~\ref{sec:graph} comes from them.
No number in this report is taken from them.
